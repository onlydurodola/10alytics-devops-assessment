# 10Alytics DevOps Assessment

A full-stack task management application demonstrating a complete CI/CD pipeline with clear separation of responsibilities:

- **Terraform** provisions the AWS infrastructure (EC2, security group, SSH key).
- **Ansible** configures the EC2 host (installs Docker, creates directories) but does **not** deploy the application.
- **CI** runs on pull requests to `main`: lint, test, and verify Docker images build.
- **CD** runs on pushes to `main`: builds and pushes backend + frontend images, copies compose files to EC2, and deploys the application — including database migrations.

**Live deployment:** `http://13.60.239.68`

## Architecture

```
Developer opens PR → GitHub Actions CI (test + lint + build check)
        │
        ▼
PR merged to main → GitHub Actions CD
  ├─ Build backend Docker image
  ├─ Build frontend Docker image (Nginx static serve)
  ├─ Push both to GHCR using GHCR_TOKEN Personal Access Token
  ├─ Copy docker-compose.yml + .env to EC2
  ├─ SSH to EC2, log into GHCR, pull images
  ├─ Run docker compose up (entrypoint runs migrations)
  └─ Verify /api/health endpoint
        │
        ▼
AWS (Terraform-provisioned)
  ├─ EC2 instance — Ubuntu 24.04
  ├─ Security group — ports 22/80/443
  └─ SSH key pair
        │
        ▼
EC2 host (Ansible-configured)
  ├─ Docker + Docker Compose installed
  ├─ /opt/10alytics-app directory ready
  └─ ubuntu user in docker group
        │
        ▼
Docker Compose on EC2
  ├─ PostgreSQL 17 container
  ├─ Flask backend container (migrations run on startup)
  └─ Nginx frontend container (proxies /api to backend)
```

## Prerequisites

Install these tools locally:

- Terraform ≥ 1.10
- Ansible
- Docker + Docker Compose
- AWS CLI (`aws configure`)
- GitHub CLI (`gh`) — optional but convenient for setting secrets

Configure AWS credentials:

```bash
aws configure
# Enter your AWS Access Key ID, Secret Access Key, default region, and output format.
```

Or place them in `~/.aws/credentials`:

```ini
[default]
aws_access_key_id = AKIA...
aws_secret_access_key = ...
```

## Provision AWS Infrastructure (Terraform)

1. Generate an SSH key pair:

```bash
ssh-keygen -t ed25519 -C "devops@10alytics.com" -f ~/.ssh/10alytics-assessment-deployer
```

This creates:

- `~/.ssh/10alytics-assessment-deployer` — private key (keep secret)
- `~/.ssh/10alytics-assessment-deployer.pub` — public key (give to Terraform)

2. Configure Terraform variables:

```bash
cd terraform
cp terraform.tfvars.example terraform.tfvars
```

Edit `terraform.tfvars` and set your values. Replace the SSH public key placeholder with the contents of your public key file (`~/.ssh/10alytics-assessment-deployer.pub`):

```hcl
aws_region     = "eu-north-1"
project_name   = "10alytics-assessment"
instance_type  = "t3.micro"
ssh_public_key = "ssh-ed25519 AAAAC3... devops@10alytics.com"
```

3. Provision:

```bash
terraform init
terraform plan
terraform apply -auto-approve
```

4. Save the outputs:

```bash
terraform output ec2_public_ip
terraform output ssh_command
```

Use the private key as the GitHub secret `EC2_SSH_KEY`, and the public IP as `EC2_HOST`.

## Configure the EC2 Host (Ansible)

Run Ansible once after Terraform to prepare the server. Ansible does **not** deploy the application.

```bash
cd ansible
ANSIBLE_HOST_KEY_CHECKING=False ansible-playbook -i inventories/production/inventory.ini playbook.yml
```

Before running Ansible, open `ansible/inventories/production/inventory.ini` and replace the example IP with the public IP from Terraform:

```ini
[web]
web_server ansible_host=YOUR_EC2_PUBLIC_IP

[web:vars]
ansible_python_interpreter=/usr/bin/python3
```

Ansible installs Docker, ensures the service is running, adds `ubuntu` to the `docker` group, and creates `/opt/10alytics-app` for the CD pipeline.

## GitHub Secrets

The CD workflow needs the following secrets. Add them in the repository settings under **Settings → Secrets and variables → Actions**, or use the GitHub CLI if you have it installed.

| Secret | Value | How to obtain |
|--------|-------|---------------|
| `EC2_HOST` | Public IP of the EC2 instance | From `terraform output ec2_public_ip` |
| `EC2_SSH_KEY` | Contents of the private SSH key | `~/.ssh/10alytics-assessment-deployer` |
| `DB_PASSWORD` | A strong password | Generate with a password manager or `openssl rand -base64 32` |
| `SECRET_KEY` | A long random string | Generate with `openssl rand -base64 48` |
| `GHCR_TOKEN` | GitHub Personal Access Token | See below |

### Creating the GHCR_TOKEN Personal Access Token

The default `GITHUB_TOKEN` does **not** have permission to push packages in a private repository. You must create a Personal Access Token:

1. Go to GitHub → **Settings → Developer settings → Personal access tokens → Tokens (classic)**.
2. Click **Generate new token (classic)**.
3. Select these scopes:
   - `write:packages`
   - `read:packages`
   - `delete:packages` (optional, for cleanup)
4. Copy the token and store it as the `GHCR_TOKEN` secret.

### Secret Reference

| Secret | Purpose |
|--------|---------|
| `GHCR_TOKEN` | Push images to GHCR and log into GHCR from EC2. |
| `EC2_HOST` | Public IP of the EC2 instance. |
| `EC2_SSH_KEY` | Private SSH key for deploying to EC2. |
| `DB_PASSWORD` | PostgreSQL password. |
| `SECRET_KEY` | Flask JWT signing secret. |

## CI/CD Pipeline

### CI — `ci.yml`

Triggers on every **pull request** to `main`:

1. **test-backend** — installs Python dependencies, lints with `ruff`, runs `pytest`.
2. **build-backend** — verifies the backend Docker image builds successfully.
3. **build-frontend** — verifies the frontend Docker image builds successfully.

No images are pushed and no deployments happen during CI.

### CD — `cd.yml`

Triggers on every **push** to `main`:

1. **build-and-push** — builds and pushes two images to GHCR:
   - `ghcr.io/onlydurodola/taskapp-backend:${GITHUB_SHA}` + `:latest`
   - `ghcr.io/onlydurodola/taskapp-frontend:${GITHUB_SHA}` + `:latest`

   GHCR authentication uses the `GHCR_TOKEN` Personal Access Token.

2. **deploy** —
   - Configures the SSH key.
   - Generates `deploy/.env` with the commit-SHA image tags, database password, and Flask secret key.
   - Copies `deploy/docker-compose.yml` and `deploy/.env` to `/opt/10alytics-app` on EC2.
   - SSHes into EC2, logs into GHCR, and runs:
     ```bash
     docker compose pull
     docker compose up -d --remove-orphans
     ```
   - The `backend` container entrypoint runs `alembic upgrade head` before starting gunicorn, applying any pending migrations.
   - Verifies the `/api/health` endpoint returns 200.

## Migrations

Database migrations are managed with **plain Alembic**. The production container entrypoint is:

```bash
#!/bin/bash
set -e
alembic upgrade head  # apply pending migrations
exec gunicorn ...     # start the app
```

This means every deployment automatically runs migrations before the new app version starts serving traffic.

## Verify the Deployment

After the CD pipeline completes:

```bash
curl http://<EC2_HOST>/
curl http://<EC2_HOST>/api/health
```

Expected `/api/health` response:

```json
{
  "status": "healthy",
  "database": {
    "ok": true,
    "tasks": 0
  }
}
```

Test signup and login:

```bash
curl -X POST http://<EC2_HOST>/api/auth/signup \
  -H "Content-Type: application/json" \
  -d '{"username":"demo","password":"DemoPass123!"}'

curl -X POST http://<EC2_HOST>/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"demo","password":"DemoPass123!"}'
```

Open the UI in a browser at `http://<EC2_HOST>/` and log in with the demo credentials.
